### 3. Spring AOP 切面（执行顺序示例）

```java
@Aspect
@Component
@EnableAspectJAutoProxy
public class ControllerAspect {

    private static final Logger LOGGER = LoggerFactory.getLogger(ControllerAspect.class);

    @Pointcut("execution(public * com.example.demo.controller.SampleController.*(..))")
    public void controllerAspect() {
    }

    @Before("controllerAspect()")
    public void doBefore() {
        LOGGER.error("--------doBefore-----------");
    }

    @After("controllerAspect()")
    public void doAfter() {
        UserInfoUtil.removeUser();
        LOGGER.error("--------doAfter-----------");
    }

    @AfterReturning("controllerAspect()")
    public void doAfterReturning() {
        UserInfoUtil.removeUser();
        LOGGER.error("--------doAfterReturning-----------");
    }

    @AfterThrowing("controllerAspect()")
    public void doAfterThrowing() {
        UserInfoUtil.removeUser();
        LOGGER.error("--------doAfterThrowing-----------");
    }

    @Around("controllerAspect()")
    public Object doAround(ProceedingJoinPoint joinPoint) throws Throwable {
        LOGGER.error("--------doAround方法执行-----------");
        return joinPoint.proceed();
    }
}
```

执行顺序（从日志可见）：`Around → Before → 业务方法 → After → AfterReturning / AfterThrowing`。

    try {
        return stringRedisTemplate.execute((RedisCallback<Set<String>>) connection -> {
            Set<String> binaryKeys = new HashSet<>();
            Cursor<byte[]> cursor = connection.scan(
                    new ScanOptions.ScanOptionsBuilder().match(prefix).count(Integer.MAX_VALUE).build());
            while (cursor.hasNext()) {
                binaryKeys.add(new String(cursor.next()));
            }
            return binaryKeys;
        });
    } catch (Exception e) {
        logger.error("redis keys方案报错-->{}", ExceptionUtil.printStrackTrace(e));
    }
    return null;
}

private void delRedisKeys(String prefix) {
    try {
        Set<String> keys = keys(prefix);
        stringRedisTemplate.delete(keys);
    } catch (Exception e) {
        logger.error("redis delRedisKeys方案报错-->{}", ExceptionUtil.printStrackTrace(e));
    }
}

## 个人踩坑记录

### Spring Boot Actuator 健康检查 vs 自定义 hello 接口

生产环境几乎每天都有 pod 重启，区别在于：

- 使用 `spring-boot-starter-actuator` 的项目：actuator 会探测项目各个中间件资源，当某个资源 down 时，k8s 判定不健康 → pod 重启。
- 使用自定义 hello controller 方式：仅仅表示项目能通，资源挂掉时未及时发现，pod 不会重启。

生产接口自动化测试只判断了 http 状态码是 success，因此可能存在「某个服务短暂不可用但没有检测出来」的情况。建议：写脚本跑 actuator，打印一天的详细信息，观察是否有中间件资源短暂不可用。

### ES 分页：偏移量分页的坑

移动端应用分页大部分用 mybatis 的 pagehelper 分页插件（偏移量分页），优点是写法简单、可看总页数和上下页；问题是数据新增或删除时分页不准确。

较差的做法：整体数据量较少时，请求第二页放大 pagesize（如 pageno=2&pagesize=10 变为 pageno=1&pagesize=20），实质相当于弱化了分页。

缓解方案：基于**游标（cursor）**的分页方式，移动端体验更好；飞书的分页接口设计也一定程度上解决了此问题。

### Cron 平台对「周一」的解析差异

- `cron.ciding.cc` 平台解析：1 = 周一
- xxl-job 平台解析：1 = 周日

配置定时任务时需注意两个平台的差异。

### IDEA Maven 本地仓库识别错误

新版 IDEA 默认把本地仓库识别为 C 盘 `.m2\repository`，需手动 `Reload All Maven Projects` 才会读取 D 盘配置；可用 `mklink` 符号链接一劳永逸解决（详见 [02-开发工具](./02-开发工具)）。
